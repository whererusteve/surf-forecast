# Notes for working on this repo

The owner (Steve) is a writer and content person, not primarily a coder. He handles prose and creative direction; explain code changes in plain language and teach where it helps.

## Architecture rules

- `app/` is a **no-build static site**: plain ES modules, Leaflet from jsDelivr with SRI hashes. No npm dependencies, bundlers or frameworks. It must keep working on GitHub Pages from a subpath, so use relative URLs only.
- `app/js/scoring.js` holds pure functions only (no DOM, no fetch). Every scoring rule change gets a test in `tests/scoring.test.mjs`; run `npm test`.
- `app/data/spots.json` is generated by `pipeline/build_spots.py`. Never hand-edit it; change the pipeline or `pipeline/known_spots.json` and rerun.
- Keep forecast points (`forecastPoints` in spots.json) around 200 or fewer. Each costs one Open-Meteo call per API per page load (limit 600/min). Tune `FORECAST_GRID_DEG` in the pipeline.
- Spot IDs (`PNW-0001`…) are reassigned on every pipeline run. Don't rely on them being stable across rebuilds.

## Forecast caching

`app/js/forecast.js` saves Open-Meteo responses in Cache Storage (`surf-forecast-v1`), not localStorage (too small, and it holds surf reports). Fresh for 1 h; used as a fallback up to 12 h old if the network fails (status line says so). Bump the cache name if the response format the app expects changes.

## Surf reports

Testers' reports are stored in localStorage (`surfReports.v1`) and emailed via `mailto:`. Each email ends with a `DATA {json}` line, the full report object from `app/js/reports.js`, so emails can be parsed in bulk later. Report choice `value`s are stored data: don't rename them, only their labels. Times display in the viewer's local time zone (BC and WA no longer always share a clock).

## Hosting

GitHub Pages deploys from the `main` branch root (classic branch mode, not Actions). Root `index.html` redirects to `app/`; `.nojekyll` stops Jekyll processing. `.github/workflows/tests.yml` only runs tests.

## Testing in a headless browser

The DFO tide API (BC) returns HTTP 500 to `HeadlessChrome` user agents, so BC tides fail in Playwright but work in real browsers. Test tides with a Washington spot (NOAA) instead. Don't spoof the user agent.

## Editorial values

No pay-to-play rankings. Respect First Nations territory and access rules. Be honest about model uncertainty in the UI.

## Backcountry Snow Finder (`snow/`, branch `backcountry-snow`)

The build brief is `prompts/backcountry-snow.md` (section 9 records Steve's decisions). Same rules as the surf app, plus:

- **Safety first.** Snow quality and avalanche hazard are never blended into one score; the official forecast is the authority; the app never calls terrain safe. See section 3 of the brief.
- `snow/data/zones-<region>.json` is generated by `snow/pipeline/build_zones.py`. Never hand-edit it. Curated inputs: `snow/pipeline/known_access.json` (trailheads, lift gates, winter road closures; entries marked `verify` need Steve), `snow/pipeline/exclusions/curated.json` (Steve's removals, shapes only, never the reasons).
- Cultural areas: wording, Nations, contacts and block/flag/seasonal rules live in `snow/content/cultural_areas.json` (Steve's file; never invent or embellish stories). Heli tenures and proposed resorts are highlighted, not removed.
- Exclusions are cut out before zones are drawn; `snow/pipeline/exclusions/sources-<region>.json` records what each source removed on the last build.
- Downloads are cached in `snow/pipeline/cache/` (git-ignored). Install with `pip install -r snow/pipeline/requirements.txt`. A rebuild takes ~1-2 min per region once the cache is warm.
- Network quirks: Overpass and Geofabrik drop connections from this cloud environment, so OSM ski-route data comes from the ohsome API (aggregates only; extraction endpoints return 403). ohsome is slow and sometimes unresponsive: `prefetch_routes.py` fills a fixed-grid cache gently; builds carry on without it and say so.
- Mountain Information Network reports and OSM GPS traces are reduced to locations as they arrive; never store or publish usernames, titles or trace links in app data.
- Avalanche terrain comes from AutoATES v2.0 (GPL-3.0, run from a pinned clone in the cache, never copied into the repo) via `snow/pipeline/autoates_tiles.py`: resumable 15 km tiles, ~10-50 min each, day-trip tiles first. In this cloud environment, background jobs die when the session idles and are capped at 2 h, so run `--day-trips --hours 1.9` and stay in the turn until it stops between tiles. Rebuild zones after new tiles land. Always label it a model estimate, never an official ATES rating. Zones it hasn't reached say "not assessed yet".
- US zones use the avalanche centre's published elevation bands (NWAC/IPAC); BC zones use a land-cover treeline estimate calibrated against them.
- Zone IDs (`S-0001`...) change on every rebuild, like the surf app's spot IDs.
- Avalanche danger panel: `snow/js/hazard.js` (pure, tested with real responses in `tests/snow/fixtures/`) and `snow/js/avalanche.js` (fetch + Cache Storage `snow-avalanche-v1`: fresh 1 h, fallback up to 12 h, then "couldn't load"). BC (north of 49°) uses Avalanche Canada's point API; the US uses avalanche.org's map layer (highest danger per forecast zone only). Until Avalanche Canada gives written permission, show ratings, problems and a link, never bulletin text. Expired forecasts are greyed out and say so. Wording lives in `snow/content/hazard.json` (Steve's file).
- Curation mode is `?curate=1` (`snow/js/curate-ui.js`, pure parts in `curation.js`). Removals live in localStorage `snowCuration.v1`; "Download for the pipeline" gives a merged `curated.json` with shapes only. Private notes never go in the repo.
- Glaciers (ESA WorldCover snow/ice) are drawn under zones; gentle glacier terrain is not a zone (Steve, 2026-11-11). Tap text lives in `snow/content/glaciers.json` (Steve's file).
